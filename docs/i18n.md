# i18n

All UI strings go through `src/lib/i18n.ts`. No external deps.

## Core
- `Lang = "en" | "fr" | "es"` — add more by extending `LANGUAGES` + `bundles`.
- `t(key, params?)` looks up `bundles[lang][key]` → fallback `bundles.en[key]` → `key`.
- Interpolation: `"Hello {name}"` → `t("hello", { name: "Bob" })`.
- Language stored in `oc.settings.language` (via `useSettings`) and mirrored to `oc.language`. `useTranslation()` hook subscribes to `storage` + `oc:language-changed` and re-renders.

## Adding a new string
1. Add `en` entry in `src/lib/i18n.ts` `en` dict, e.g. `"mySection.title": "My Title"`.
2. Add `fr` / `es` translations.
3. Use `const { t } = useTranslation();` and `{t("mySection.title")}` in JSX.

## Language setting
Settings drawer → Language section (`src/components/SettingsDrawer.tsx:310`) maps `["en","fr","es"]` to `update({ language: l })`. `useSettings` persists and dispatches `oc:language-changed`. On first run `detectLang()` picks `fr`/`es` from `navigator.language`, else `en`.

## Plugins

Plugins receive:

```js
export default function activate(api) {
  // api.t — bound to plugin id, checks plugin bundle first
  // api.i18n.register — merge new keys
  // api.i18n.getLanguage — current Lang

  api.i18n.register({
    en: {
      "title": "Lights & Curtains",
      "desc": "Control your Tuya lights",
      "open": "Open",
    },
    fr: {
      "title": "Lumières & Rideaux",
      "desc": "Contrôlez vos lumières Tuya",
      "open": "Ouvrir",
    },
    es: {
      "title": "Luces y Cortinas",
      "desc": "Controla tus luces Tuya",
      "open": "Abrir",
    }
  });

  function Settings({ open }) {
    if (!open) return null;
    // api.t("title") → looks in plugin bundle first
    // api.t("plugins.title") → falls back to core bundle
    return api.h("div", null, api.t("title"));
  }

  // global keys (prefix with plugin id): register then use core t
  // register: { en: { "tuya.lights": "Lights" } }
  // use: t("tuya.lights") via `import { t } from "../../lib/i18n"`

  return { Settings };
}
```

Rules:
- Keys are flat strings — prefix with your plugin id to avoid collisions, e.g. `"myPlugin.title"`.
- `register` is idempotent and merges; call once in `activate` before first render.
- `api.t` inside plugin first checks `pluginBundles[pluginId][lang][key]`, then `pluginBundles[*][lang][key]`, then `t("pluginId.key")`, then core `t(key)`.

## Menus / submenus

Every menu now uses `t()`:
- Titlebar, Sidebar tabs + session context menu, FileTree context menu, Composer placeholders, PermissionBar, QuestionPopup, BrowserBar, GitPanel header, ChatPage banners.
- ContextMenu is generic — callers pass already-translated `label`.

Add new menus the same way: get `t` via `useTranslation()` (React) or `api.t` (plugins).

# Audit fixes — 02: Rust voice / update / misc (browser, discord, pty, remote, terminals)

## Scope

Files touched (only these): `src-tauri/src/voice.rs`, `src-tauri/src/update.rs`,
`src-tauri/src/browser.rs`, `src-tauri/src/discord.rs`, `src-tauri/src/pty.rs`,
`src-tauri/src/remote.rs`, `src-tauri/src/terminals.rs`, `src-tauri/Cargo.toml`
(plus `src-tauri/Cargo.lock`, auto-regenerated by `cargo check` when
`whisper-rs` was removed). No command names, arg names, or frontend contracts
changed. One dependency removed (see C7). Line numbers below refer to the
audited tree.

## Changes

### A — blocking downloads off the async pool

- `voice.rs:236` (`voice_download`) — curl body (up to `--max-time 1800`) moved
  into `tauri::async_runtime::spawn_blocking` (mirrors the existing pattern at
  `voice.rs:335`/`voice_transcribe`). URL/key validation stays on the async
  path; curl + `.part` cleanup run on the blocking pool. Why: a 30-min download
  pinned one tokio worker.
- `update.rs:66` (`update_download`) — same wrap: curl + sha256 + zip
  extraction all moved into one `spawn_blocking` body.

### B — update.rs

1. `update_download` — see A above.
2. `update.rs:17–23` `sha256_of(path)` → `sha256_of_reader(&mut dyn Read)`
   streaming in 64 KiB chunks (File + BufReader at the call site); the
   extraction pass now opens the zip with `File + BufReader` instead of
   `std::fs::read` into RAM. Net: a ~300 MB release zip is streamed twice off
   disk instead of being held in RAM twice. The zip file is deleted after the
   archive is closed (block-scoped archive so the delete isn't blocked by the
   open file handle on Windows).
3. `update.rs:335–433` relaunch fallback — 4 tiers (batch → powershell → pwsh →
   direct spawn) cut to 2 (batch → direct spawn). The PowerShell tiers were a
   second wait-and-start implementation for the same single-instance-mutex
   race the batch already solves with a fixed delay.
4. `update.rs:117–181` `update_stage_local` — real body now `#[cfg(debug_assertions)]`;
   release gets a same-signature stub (`folder`, `version` arg names preserved)
   returning `Err("update_stage_local is debug-only")`. Staging code ships
   zero bytes in release. **lib.rs note:** the `invoke_handler` entry at
   lib.rs:2105 can be dropped later by the lib.rs owner together with the
   release stub and the frontend "debug local update" UI.

### C — voice.rs dead code / duplication

1. `tts_stream` (voice.rs:1543–1612) — zero frontend callers verified. Replaced
   by a signature-identical stub returning
   `Err("tts_stream was removed — use tts_speak / tts_speak_pcm")`. **lib.rs
   note:** the registration line at lib.rs:2053 must be dropped by the lib.rs
   owner; deleting the fn without dropping the registration breaks
   `generate_handler!` (cannot edit lib.rs from this pass).
2. `f32_to_wav` (voice.rs:1264–1286) deleted — byte-identical to
   `pcm_f32_to_wav_bytes` (voice.rs:454). `tts_speak` now calls
   `pcm_f32_to_wav_bytes(&samples, 24000)`.
3. `kokoro_voice_label` (voice.rs:1026–1041, `#[allow(dead_code)]`) deleted.
4. Whisper CLI selection + GPU→CPU fallback + "gpu build ran without cuda"
   stderr sniff duplicated in `voice_transcribe` (379–425) and
   `voice_transcribe_pcm`'s CLI fallback (776–812) → extracted into one local
   helper `transcribe_via_cli(mp, tmp, translate, want_gpu)`; both call sites
   now pass model path + temp wav + flags and get back `TranscribeOut`.
   Micro-fix included: the temp WAV is now removed on ALL paths (the old
   CPU-retry-failure path leaked it).
5. `has_voice` boolean soup at voice.rs:1448/1514/1559 → one local helper
   `kokoro_voice_installed(id)` (same precedence semantics:
   `per-voice file || legacy voices.bin || (voices dir non-empty)`).
6. rename-or-copy fallback idiom ×3 (voice.rs:301–309, 1301–1305, 1347–1351) →
   one local helper `rename_or_copy(from, to)`. Edge-message change: the
   0-byte-copy error is now `"empty file"` instead of `"empty model file"`
   (only reachable when the downloaded part itself is empty).
7. whisper-rs in-process path deleted: `whisper_cache` module (623–646), the
   `#[cfg(feature = "whisper")]` block in `voice_transcribe_pcm` (681–713), the
   `whisper` cargo feature, and the `whisper-rs` optional dep in Cargo.toml.
   `Cargo.lock` regenerated by cargo — `whisper-rs` and its dependency tree
   (~140 lock lines) are gone. No build script or CI ever enabled the feature
   (verified by grep over `*.ps1`, `*.sh`, `*.toml`, `*.json`, `*.rs`, `*.ts*`).
   CLI + persistent whisper-server backends unchanged.

### D — browser.rs lock poisoning hardening

All 15 `state.0.lock().unwrap()` sites (browser.rs 119, 123, 151, 182, 199,
208, 220, 232, 463, 470, 499, 513, 529, 543, 568) →
`.unwrap_or_else(|e| e.into_inner())`. A panic while a lock is held no longer
turns every later browser/tiktok invoke into a panic-through-poison; the guard
still sees the actual data. (Same pattern already used in voice.rs/pty.rs/
remote.rs.)

### E — discord.rs

`discord_set` (125–147, sync fn with `std::thread::sleep(200ms)` + blocking
named-pipe `connect()` on the main thread) → `async fn`:

- `ensure_client` split: cheap part (id-change reset + client create, no IO)
  stays inline as `ensure_client_created`; the blocking `connect()` +
  `set_activity()` run inside `tauri::async_runtime::spawn_blocking`.
- The client is temporarily `take()`n out of the state mutex, moved into the
  blocking task (DiscordIpcClient is `Send` — it wraps a `std::fs::File` named
  pipe), and put back afterwards. The `Activity` (which borrows the owned
  strings) is built inside the task so borrows stay local.
- Semantics preserved: retry loop (2 attempts), 200 ms sleep between attempts
  (now on the blocking pool), connect-failure keeps the existing client,
  set_activity-failure closes + drops it so the retry gets a fresh one,
  `connected` flag transitions identical.
- `discord_clear`/`discord_status`/`discord_get_start_ts`/`discord_close` left
  sync — their named-pipe writes are single fast packets, no sleep/connect
  loop.

### F — remote.rs

`remote_terminals` (840, sync fn doing a blocking ssh probe with
ConnectTimeout 10 s on the main thread) → `async fn`; the `exec_remote` probe
moved into `spawn_blocking`. Return type changed `Vec<TerminalProfile>` →
`Result<Vec<TerminalProfile>, String>` (Tauri requires async commands that take
references to return a `Result`). Frontend-transparent:
`useTerminalProfiles.ts` consumes it via `invoke().then/.catch`, so `Ok(vec)`
resolves exactly as before and the (previously impossible) `Err` becomes a
rejection the existing catch already handles.

### G — pty.rs

`pty_spawn` / `pty_kill` (sync fns with fixed 90 ms settle sleeps + ConPTY
creation on the main thread) → `async fn`:

- `pty_spawn`: id==0 check + quick map check/replace-kill stay inline (fast
  lock ops); the entire ConPTY openpty/spawn/reader-waiter-thread body moved to
  a sync helper `pty_spawn_blocking` executed via `spawn_blocking`, returning
  the `Arc<PtySession>`; the final map insert/max-terminals-kill block stays in
  the async command (same order as before: threads spawned, then insert).
- `pty_kill`: kill decision inline (fast), the 90 ms settle sleep moved to
  `spawn_blocking`.
- All timings identical (90 ms sleeps kept verbatim).

### H — terminals.rs

The 20-line Lxss registry enumeration loop duplicated inside `wsl_distros`
(terminals.rs:322–344 and 488–507) → one local fn `lxss_registry_names()`
(`#[cfg(windows)]`, returns the names; both sites call it — primary pass and
fallback pass, same HKCU→HKLM order and dedupe).

## Regression watchpoints

**TTS install (kokoro model + voices + GPU pack)**
- Smoke: Settings → Voice → install Kokoro model (downloads via
  `voice_download` → `install_piper_bin`), install a voice
  (`install_tts_voice_part`, both zip and raw .bin paths), install the GPU
  pack (`install_kokoro_gpu_part` → `tts_status.gpu` true). Then Settings →
  "Clean state" → `voice_remove_all` wipes everything.
- Watchpoint: cross-volume rename fallback now shared — a 0-byte part now
  errors with `"empty file"` (was `"empty model file"`) only in the copy
  branch.

**STT via CLI + whisper-server**
- Smoke: mic push-to-talk with a CLI engine installed
  (`voice_transcribe` → `transcribe_via_cli` → `run_whisper`); then with
  whisper-server present (`voice_transcribe_pcm` → `ensure_whisper_server`
  reuse across utterances); then GPU path (`gpu: true` → bin-gpu engine →
  "gpu build ran without cuda" note path); then delete the GPU engine
  (`voice_remove_gpu`) → falls back to CPU.
- Watchpoint: `TranscribeOut { text, engine, note }` shape unchanged; error
  strings unchanged; server self-recovery kill-on-failure unchanged; temp WAV
  now also cleaned when the CPU retry itself fails (was leaked before).

**Updater download/install flow**
- Smoke (debug): `update_stage_local` with a local folder containing
  `opencode-gui.exe` → `update_install` → app exits → relaunched as new
  version (check `%TEMP%\oc-update-trace.log`). Release smoke (only in a test
  env): `update_download` of a real release zip + sha → verify checksum error
  on tampered sha, then `update_install` swap.
- Watchpoint: relaunch fallback is now 2 tiers. If a machine ever fails BOTH
  the batch write AND the direct spawn, nothing relaunches (before: three
  more attempts that all reused the same broken spawn semantics). Trace line
  `batch not spawned, trying direct spawn` marks the path.

**Discord presence**
- Smoke: enable presence with Discord running → `discord_set` shows activity
  (status "connected"); close Discord → `discord_set` errors once with
  "discord not available", retry path still works when Discord returns;
  `discord_clear` clears; quit with presence on → pipe closed cleanly.
- Watchpoint: during the blocking connect the state mutex no longer holds the
  client (it's `take()`n) — `discord_status` may briefly report "idle"/
  "disconnected" mid-set; before it could briefly report the same because
  locks were dropped between steps. Final state identical.

**PTY spawn/kill**
- Smoke: open 3+ terminals (ConPTY creation now on blocking pool — UI stays
  responsive while 3 spawn at once); type + resize each; close one mid-output
  (`pty_kill`) → `pty://exit` arrives, instance auto-closes; open the 9th →
  "max terminals (8) reached" error path still kills the just-created PTY
  (RC-07 leak guard intact, now in the async fn after the blocking spawn).
- Watchpoint: spawn error strings unchanged (`"shell not found: …"`, ssh
  unreachable message); `pty://frame`/`pty://exit` payloads unchanged.

**Remote terminals**
- Smoke: connect an ssh workspace → terminal picker shows `ssh-*` profiles;
  kill the host network and reopen the picker → returns `[]` within the ssh
  timeout instead of freezing the UI; circuit breaker still trips
  ("failed recently" fast-fail).
- Watchpoint: return type is now `Result` — only observable as a rejected
  promise on total failure, which the frontend already handles.

**WSL distro listing**
- Smoke (Windows with WSL): Settings → Terminals lists `WSL: <distro>` entries
  from registry first; uninstall a distro and re-list → registry result
  reflects it; with WSL installed but no distros → generic "WSL" entry still
  appears unless a no-distro message was seen.
- Watchpoint: pure extraction, zero logic change; `run_wsl` CLI probes still
  run when the registry returns nothing.
